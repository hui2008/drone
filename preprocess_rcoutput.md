# Preprocessing `libraries/AP_HAL/examples/RCOutput/RCOutput.cpp`

This note captures how `libraries/AP_HAL/examples/RCOutput/RCOutput.cpp` was preprocessed from the current `sitl` build configuration.

## Purpose

Preprocessing lets you inspect what the compiler sees after:

- `#include` expansion
- macro expansion
- forced includes such as `ap_config.h`

This is useful for understanding generated code such as `AP_HAL_MAIN()` expansion.

## Prerequisite

`build/sitl` is generated by:

```bash
./waf configure --board sitl
```

This step creates build-specific files such as `build/sitl/ap_config.h` and other generated build metadata. The preprocess commands in this note depend on that configured build tree, so they are not expected to work before `build/sitl` exists.

## Source Compile Context

The exact compile flags were taken from:

- `build/sitl/compile_commands.json`

The matching source entry is:

- `libraries/AP_HAL/examples/RCOutput/RCOutput.cpp`

- Created with `-E`

- Derived from `full.ii`

- Derived from `full.ii`
- Keeps only sections attributed to `libraries/AP_HAL/examples/RCOutput/RCOutput.cpp`
- Best for seeing the expanded body of the original source file

## Argument Breakdown

The preprocess command reuses the exact compile flags from `compile_commands.json`, then swaps compile mode for preprocess mode.

### Compiler executable

- `/usr/bin/g++`
  Uses the same C++ compiler selected for the `sitl` build.

### Language and code generation mode

- `-std=gnu++11`
  Compile as GNU C++11, matching the ArduPilot build.
- `-O3`
  Keep the same optimization mode as the compile command. Optimization does not matter much for preprocessing, but preserving the compile command reduces surprises.
- `-fdata-sections`
  Put each data item in its own section for later linker garbage collection.
- `-ffunction-sections`
  Put each function in its own section for later linker garbage collection.
- `-fno-exceptions`
  Build without C++ exceptions.
- `-fsigned-char`
  Treat plain `char` as signed on this target.
- `-fsingle-precision-constant`
  Prefer single-precision floating constants where applicable.
- `-ffile-prefix-map=../..=../..`
  Normalize embedded source paths in compiler output.

### Warning and error policy

- `-Wall`, `-Wextra`
  Enable the standard warning sets.
- `-Wpointer-arith`
  Warn on questionable pointer arithmetic.
- `-Wno-unused-parameter`
  Suppress unused parameter warnings.
- `-Wno-missing-field-initializers`
  Suppress warnings for omitted struct initializer fields.
- `-Wno-redundant-decls`
  Suppress duplicate declaration warnings.
- `-Wno-unknown-pragmas`
  Ignore pragmas unknown to this compiler.
- `-Wno-expansion-to-defined`
  Suppress warnings about `defined` used through macro expansion.
- `-Wno-invalid-offsetof`
  Suppress warnings for `offsetof` patterns used in the codebase.
- `-Wfatal-errors`
  Stop after a fatal compile error.
- `-Wno-trigraphs`
  Ignore trigraph warnings.
- `-Wuninitialized`, `-Warray-bounds`
  Extra diagnostics enabled explicitly in addition to the base warning sets.

### Forced includes

- `-include ap_config.h`
  Inject `ap_config.h` before normal source processing. This is important because much of the build configuration is made visible through that header.

### Include search paths

- `-Ilibraries`
- `-Ilibraries/GCS_MAVLink`
- `-Imodules/DroneCAN/libcanard/dsdlc_generated/include`
- `-I../../modules/DroneCAN/libcanard`
- `-I../../libraries/AP_DroneCAN/canard`
- `-I.`
- `-I../../libraries`
- `-I../../modules/littlefs`
- `-I../../libraries/AP_Common/missing`
- `-I../../modules/lwip/src/include`
- `-I../../libraries/AP_Networking/config`
- `-I../../libraries/AP_Networking/lwip_hal/include`

These directories tell the preprocessor where to resolve `#include` directives.

### Dependency generation

- `-MMD`
  Generate dependency information for user headers. This matters for normal compilation, not for understanding the preprocessed output.

### Preprocess-only switches

- `-E`
  Stop after preprocessing. Do not compile or assemble.
- `-P`
  Remove `#line` markers from the output, making the file flatter and easier to read.

If `-P` is removed, the output keeps markers such as `# 1 "file"`, which is how `full.ii` was generated.

### Input and output paths

- `../../libraries/AP_HAL/examples/RCOutput/RCOutput.cpp`
  The source file being preprocessed, relative to `build/sitl`.
- `-o libraries/AP_HAL/examples/RCOutput/RCOutput.cpp.ii`
  Write the preprocessed output under the build directory.

## Why The Files Are Large

Preprocessed files are much larger than the original source because they inline:

- all transitive headers
- all macro expansions
- all forced includes

Even a small example source can expand into thousands of lines.

## Key Macro Expansion Seen Here

In `source_only.ii`, the `AP_HAL_MAIN()` expansion becomes:

```cpp
AP_HAL::HAL::FunCallbacks callbacks(setup, loop); extern "C" { int main(int argc, char* const argv[]); int main(int argc, char* const argv[]) { hal.run(argc, argv, &callbacks); return 0; } };
```

- `Tools/scripts/preprocess_source.py`

```bash
Tools/scripts/preprocess_source.py libraries/AP_HAL/examples/RCOutput/RCOutput.cpp
```
